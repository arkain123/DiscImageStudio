# Проверка физической модели генерации CD / DVD

Дата проверки: 2026-09-21. Объект — текущая рабочая область `DiscImageStudio-GitHub` (включая ещё не закоммиченную реализацию калибровки), базовый коммит `6c55a18`. В этот раз выполнены только сверка со стандартами, аудит исходного кода и независимая численная проверка; генератор, пресеты и поведение записи не изменялись.

## Выводы

В базовой формуле спирали и длине сектора DVD не обнаружено вычислительных ошибок. Однако текущая модель не может по номинальным параметрам стандарта точно предсказать угол на реальной поверхности диска: параметры CD по умолчанию имеют проблему геометрической согласованности; однолинейная калибровка при фиксированной линейной плотности поглощает ошибку плотности в радиус; граничные эффекты конечного потока при чередовании CD и опорная временная последовательность также не входят в геометрическую модель. Кроме того, отсутствует проверка соответствия типа записываемого диска и модели генерации.

Только по этому аудиту нельзя определить единственную причину изгиба на каком-либо реальном диске, и не следует просто заменять длину бита DVD на другое номинальное значение как исправление.

## Основа стандартов и область применимости

- Официальный [ECMA-359, первое издание, 2004](https://ecma-international.org/wp-content/uploads/ECMA-359_1st_edition_december_2004.pdf): однослойный DVD-R, в основном проверены §§10.7–10.9, 18–23, 24.2. Сверены оригинальные страницы PDF 28, 29, 52, 56.
- Официальный [ECMA-267, третье издание, 2001](https://ecma-international.org/wp-content/uploads/ECMA-267_3rd_edition_april_2001.pdf): DVD-ROM, в основном проверены §§10.6, 18–21. Его нельзя использовать для замены всех правил записываемых носителей.
- Официальный [ECMA-130, второе издание, 1996](https://ecma-international.org/wp-content/uploads/ECMA-130_2nd_edition_june_1996.pdf): геометрия CD-ROM и справочник по общему кодированию CIRC, §§8.6, 11.3–11.4, 19.4, приложение C. Аудиодорожка не равна дорожке данных CD-ROM.
- Официальный [ECMA-394, первое издание, 2010](https://ecma-international.org/wp-content/uploads/ECMA-394_1st_edition_december_2010.pdf): CD-R, многоскоростная запись, предварительная канавка и совместимость с Red Book, §§1.2, 2.4–2.5. Этот документ через ссылки на Red Book задаёт часть геометрических требований и не перечисляет напрямую полную таблицу геометрии CD.

Ключевые ограничения ECMA-359 перечислены ниже; все они являются требованиями стандарта и не могут считаться измеренными значениями какого-либо конкретного диска:

| Пункт | Ограничение | Пункт стандарта |
|---|---|---|
| Радиус начала данных | 23,9–24,0 mm | 10.7.1.2, в оригинале диаметр 48,0 mm, допуск −0,2/+0,0 mm |
| Радиус конца данных диска 12 cm | не более 58,0 mm | 10.7.1.2 |
| Средний шаг дорожек | 0,74 ± 0,01 μm | 10.8 |
| Отклонение локального шага дорожек | максимум ±0,03 μm относительно 0,74 μm | 10.8 |
| Средняя длина канального бита | 133,3 ± 1,4 nm | 10.9 |
| Первый PSN области данных | 0x030000, физические секторы непрерывны без промежутков | 24.2 |

Нижний предел диаметра начала данных ECMA-267 отличается от DVD-R: в §10.6.1 указано 48,0 mm с допуском −0,4/+0,0 mm. Нельзя смешивать допуски начала из двух стандартов.

## Подтверждённые корректные части

Число канальных битов на сектор DVD составляет `13 × 2 × (32 + 1456) = 38688`, на ECC-блок из 16 секторов — 619008 битов. Значения, используемые в `DvdEccBlockEncoder.cs:8`, корректны; в смещении секторов, кадрах синхронизации и чередовании строк PO не обнаружено общего пропуска в расчёте длины.

Текущая длина дорожки:

```text
CD:  L = (N / 75) × v                         [mm]
DVD: L = N × 38688 × channelBitLengthNm × 10^-6 [mm]
```

`CdDiscParameters.cs:59–75` использует приближение площади при постоянном шаге дорожек, `ArchimedeanSpiral.cs:33–70,115–120` — точную длину дуги. Приближённые соотношения: `pitch = π(ro²−ri²)/L`, `θ = 2L(r−ri)/(ro²−ri²)`. Разница полного угла по диску между приближением CD и точной спиралью около 0,000135°, что не может объяснить заметный на глаз изгиб. В точном обратном решении длины дуги DVD, преобразовании нанометров в миллиметры и направлении координат изображения по умолчанию также не обнаружено ошибок.

Linking DVD-R используется в特定 случаях инкрементального добавления; §24.2 явно указывает непрерывность секторов. Нет оснований единообразно добавлять к каждому ECC-блоку так называемый скрытый промежуток.

## Обнаружение первое: комбинация параметров пресета CD 80 минут по умолчанию нерациональна

`src/DiscImageStudio.Core/Presets/built-in-disc-presets.json:6–12` одновременно использует 359849 секторов, 24,5–56,8 mm и 1200 mm/s. Обратный расчёт по фактической формуле генерации:

| Пресет | Подразумеваемый шаг дорожек (μm) |
|---|---:|
| CD 80 минут по умолчанию | 1,432856 |
| CD 74 минуты по умолчанию | 1,548384 |
| Пресет CD Ritek aqua с измеренным радиусом | 1,492598 |
| Пресет Verbatim CD с измеренным радиусом | 1,500257 |
| DVD 12 cm по умолчанию | 0,739837 |
| Пресет Verbatim DVD-R с измеренным радиусом | 0,738304 |

Диапазон шага дорожек в ECMA-130 §11.3 — 1,5–1,7 μm; диапазон базовой скорости сканирования в §11.4 — 1200–1400 mm/s. Комбинация по умолчанию CD80 явно не может служить универсальным точным пресетом, соответствующим этому геометрическому диапазону. Её начальная точка 24,5 mm также не может напрямую приравниваться к началу области пользовательских данных по §8.6 (24,8–25,0 mm).

Это проверка комбинации параметров программного обеспечения, а не вывод о непригодности CD-R диска пользователя. Пресеты, помеченные как измеренные, всё равно фиксированно используют 1200 mm/s, что не означает, что линейная плотность также измерена. Нельзя самовольно менять измеренные пользователем радиусы только ради попадания в диапазон стандарта.

## Обнаружение второе: допуски стандарта намного превышают требуемую для рисования точность накопленного угла

`ImageTargetMapper.cs:58–77`, `FastDispersionImageWriter.cs:345–365` по ёмкости, двум радиусам и фиксированной длине бита обратно вычисляют постоянный шаг дорожек. Параметры DVD по умолчанию дают около 45956,06 оборота. Стандарт допускает локальные изменения шага дорожек, а 58 mm — верхний предел, поэтому эти входные данные могут составлять лишь начальную модель.

Чувствительность по числам (во всех случаях изменяется один вход, остальные остаются неизменными):

- Изменение длины бита DVD на 10 ppm изменяет накопленный угол по всему диску примерно на 165,44°.
- При изменении длины бита DVD с 133,33 на 133,3 nm накопленный угол изменяется примерно на 10,34037 оборота.
- При увеличении внутреннего или внешнего радиуса DVD на 0,001 mm накопленный угол изменяется примерно на −201,76°.

Приведённые значения — это разность фаз модели, а не измеренная ошибка реального диска. 133,33 nm находится в пределах допуска стандарта; 133,3 nm также не является истинной точной длиной бита каждого диска. Слепая замена номинального значения может существенно изменить результат генерации.

## Обнаружение третье: одна радиальная линия не может независимо подтвердить радиус и линейную плотность

`CalibrationTarget.cs:468–473` фиксирует линейную скорость / длину бита, `CalibrationCrossFitter.cs:73` подгоняет только два радиуса и общий поворот; текущий процесс не использует соответствие исходных радиусов концентрических окружностей.

Независимый контрпример: модель генерации DVD `(ri=24, ro=58, bit=133.33)`, предполагаемая истинная модель `(24,58,133.3)`. При фиксированной подгоняемой длине бита 133,33 достаточно изменить кандидатные радиусы примерно на `(24.00540257,58.01305620)` и затем скорректировать общий поворот, чтобы в диапазоне 25–57 mm почти полностью воспроизвести ту же самую кривую изгиба (максимальная фазовая невязка при точном расчёте длины дуги по 2049 точкам около 2,04×10^-10 rad). Кандидат находится в пределах поиска по умолчанию ±0,02 mm. Это прямая проверка после аналитического построения кандидата; утверждение, что текущий оптимизатор обязательно вернёт эту группу кандидатов, не делается.

Поэтому низкая невязка может быть лишь интерпретацией ошибки длины бита как ошибки радиусов. Текущая функциональность может давать полезные компенсационные параметры, но результат следует понимать как «эквивалентные параметры в предположении фиксированной линейной плотности». Чтобы подтвердить истинные физические радиусы и плотность, нужно добавить кольца с известными исходными радиусами, известные позиции данных или независимые измерения границ; простое добавление ещё одного подгоняемого параметра всё равно не решит недостаток информации.

## Обнаружение четвёртое: компенсация чередования CD имеет граничный эффект конечного потока; физическое начало временной последовательности требует проверки

Таблица задержек в `CddaInterleaver.cs:8–16` соответствует путям данных на Figure C.4 ECMA-130 и не является ошибочным повторным чередованием. Независимая симуляция меток подаёт существующий компенсированный PCM в 24 пути данных стандартного прямого CIRC: в тесте на 10 секторов все 20856 позиций установившихся данных совпадают, но комбинированный результат — целевой рисунок целиком задерживается на 111 кадров.

Нужно строго различать две вещи:

- **Определённое явление конечного потока:** инициализация создаёт 1332 нулевых байта-заполнителя; 1332 целевых байта в конце, распределённые по последним 108 кадрам, не выводятся. `Flush` в `CddaInterleaver.cs:46–55` обрабатывает только хвост сектора и не опустошает кольцевой буфер при вводе целыми секторами. Это влияет на границы рисунка.
- **Условное физическое смещение:** 111 кадров — это комбинированная задержка при опорной временной последовательности Figure C.4, около 15,102 ms, что при 1200 mm/s составляет около 18,122 mm длины дуги. Если это не компенсируется началом временной последовательности в цепочке записи, угловая разница меняется с радиусом и не может быть устранена только начальным углом. Связь с ATIP, INDEX 01 и началом данных на реальном диске ещё не измерена, поэтому нельзя прямо объявлять это подтверждённым смещением на реальном диске.

`CdTrackGenerator.cs:229–246` выполняет выборку по globalByte без добавления указанной временной последовательности; геометрическая калибровка также не включает этот уровень кодирования. Существующее пояснение о совместимости уже указывает, что предпросмотр не моделирует полный CIRC/EFM. Требуется дополнительная сквозная проверка физической временной последовательности; нельзя доказывать правильность положения на поверхности диска только совпадением генерации и предпросмотра из одного источника.

## Обнаружение пятое: тип записываемого носителя не сопоставляется с моделью

`WindowsImapiBurner.cs:151–166,377–390` проверяет только поддержку IMAPI, пустое состояние и ёмкость, но не запрашивает фактический физический тип диска. Генератор при этом использует однослойный ID (`DvdDataFrameBuilder.cs:41`) и однослойную однонаправленную спираль.

Это означает отсутствие активной блокировки других физических форматов, таких как двухслойный DVD, DVD-RAM и т. п. То, что IMAPI может записывать на некоторый носитель, не означает применимости текущей модели рисования; фактическая возможность начала записи всё равно зависит от устройства и состояния. Переключение слоёв двухслойного диска, направление второго слоя и длина бита не моделируются.

Для проверки соответствия можно использовать [CurrentPhysicalMediaType](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nf-imapi2-idiscformat2data-get_currentphysicalmediatype) и [перечисление физических носителей](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/ne-imapi2-imapi_media_physical_type) от Microsoft.

## Рекомендуемый порядок исправлений

1. Добавить для пресетов проверку подразумеваемого шага дорожек, различать начальные значения стандарта, измеренные значения и значения, полученные компенсацией; в первую очередь обработать комбинацию CD80 по умолчанию. Явно указать, какой позиции данных соответствуют начальный и конечный радиусы, и разделить диапазон обрезки рисунка и привязку дорожек.
2. Проверить совместную временную последовательность чередования CD, начала аудиодорожки и цепочки записи; затем исправить смещение выборки и стратегию начала/конца, сохраняя итоговое число секторов неизменным.
3. Добавить в калибровку независимое ограничение по радиусу или позиции данных. Если измеренная невязка всё ещё содержит систематический локальный изгиб, затем оценивать модель с переменным шагом дорожек / фазовой коррекцией.
4. Перед записью проверять соответствие фактического типа носителя и ёмкости выбранной модели.

В этот раз не выполнялись запись на реальный диск или измерение оптической яркости. Проверка включала оригинальные тексты стандартов и страницы, пересчёт формул, численное сопоставление точной спирали, контрпример неидентифицируемости параметров и симуляцию меток путей данных CIRC; эти проверки не расширяются до заявлений о полной оптической симуляции или сертификации точности на реальном диске.

Материалы для воспроизведения аудита находятся в корневом каталоге рабочей области `tmp/standards-audit/`: `circ-audit.py`, `circ-audit-result.json`, `geometry-audit.py`, `geometry-audit-result.json`, а также извлечённый текст двух пользовательских PDF и ключевые оригинальные страницы.
