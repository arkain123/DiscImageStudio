# Однослойный BD-R: анализ плотности переходов по байтам и битовым периодам

2026-10-24. На основе предоставленного ISO/IEC 30190:2021, в особенности разделов 13.15–13.18 и Figure 40/41, а также численных экспериментов с использованием цепочки EDC, скремблирования, LDC/BIS, DC и 17PP данного проекта. Рассматривается только однослойный диск.

**Если целевой показатель — общая плотность переходов, стоит использовать шаблоны, построенные по битам.** Лучшая базовая линия из повторяющихся байтов в полном кластере имеет плотность около **19,20% / 38,61%**; с учётом физического чередования и границ DC-сегментов измеренные битовые периодические схемы достигают **15,95% / 43,37%**. Разница плотностей между краями возрастает с 19,41 до 27,42 процентного пункта, то есть примерно на 41%. Это результаты цифрового кодирования; отражённая яркость реального диска и направление чёрного/белого пока не определены. Текущий рисунок использует указанное ниже **смещение по количеству 3T / 6T**, выбираемое пользователем, а не крайние по плотности схемы из этого документа.

## Подключение к рисунку по количеству 3T / 6T

Используется полный кластер с теми же 958 272 канальными битами; подсчитывается **абсолютное число** полных интервалов 3T или 6T между соседними modulation ONE. Учитываются и mark, и space; это не коэффициент заполнения уровней NRZI и не рейтинг `целевое число run / общее число run`.

| Край изображения по умолчанию | Q в скремблированной области | Целевое число run в базовом кластере | Доля целевых run | Диапазон целевого количества по четырём адресам |
|---|---|---:|---:|---:|
| Тёмная часть (0–127), смещение к 3T | `AA` | 265 136 | 85,4164% | 264 946–265 186 |
| Светлая часть (128–255), смещение к 6T | `44` | 116 575 | 62,6862% | 116 470–116 659 |

Оба значения дают наибольшее целевое количество среди всех 256 повторяющихся байтов при базовом PSN `0x100000`. У `22` наибольшая доля 6T — 62,7744%, но только 116 402 случая 6T, что меньше, чем у `44`, поэтому в количественном режиме выбирается `44`. При повторной проверке на четырёх адресах `0x100000`, `0x234560`, `0x6D3A00`, `0xCA73E0` среднее число 6T у `44` составляет 116 559,5, что немного выше 116 526,5 у `11` и 116 457 у `22`; это не означает, что оно оптимально на каждом адресе.

Производственный `BluRayRunLengthMapping` выбирает `AA` / `44` по порогу 128 и может инвертировать направление чёрного/белого; `BluRayImagePayloadMapping` выполняет выборку по положению изображения, а потоковый генератор компенсирует скремблирование и выводит host payload. Края изображения, EDC, ECC, BIS, DC и синхронизация вносят другие длины run, поэтому «смещение к 3T / 6T» не равно чистым 3T / 6T. Распределение тёмного/светлого по умолчанию — это обратимое соглашение об изображении, не откалиброванное по отражённой яркости реального диска.

Приведённые значения получены с текущей диагностической моделью жадного DC; исходные количества см. в `Cluster.RunCounts` файла `all-bytes.json`. Архитектурная регрессия проверяет смещение количества на обоих краях — в начале и в конце диска — через полное кодирование RUB, а также проверяет скремблирование и позиции ECC для смешанного изображения. Командная строка и способ использования см. в [описании Blu-ray](ADDING_BLURAY.md).

## Методика измерения

- Плотность переходов = число modulation ONE / число канальных битов. ONE означает одно переключение NRZI; нельзя подменять его долей ONE среди уровней NRZI.
- Q — это **целевой payload после скремблирования**. В host payload следует записывать `Q XOR маска скремблирования`; прямое циклическое повторение исходных host-байтов потеряет целевой шаблон.
- Результат чистого 17PP не содержит DC, ECC, BIS, синхронизации; он вычисляется точно по независимой стандартной таблице и конечному автомату.
- Полный кластер генерируется из 65 536 host bytes; статистика охватывает `496 × 1932 = 958272` канальных битов, включая EDC, LDC parity, BIS, DC, синхронизацию; без run-in/out/Guard3, но с использованием уровня и DSV на конце run-in.
- PSN по умолчанию — `0x100000`, address flags и user control data нулевые. Кандидаты дополнительно проверяются на `0x234560`, `0x6D3A00`, `0xCA73E0`.
- Основные результаты используют текущий диагностический алгоритм жадного DC: будущие управляющие биты временно считаются нулевыми. Он не гарантирует совпадения с решениями устройства записи; все 0, все 1 и случайный DC с фиксированным seed — дополнительные испытания чувствительности, а не реальный рецепт записи.

## Базовая линия по всем 256 байтам

При непрерывном повторении одного Q-байта в установившемся режиме без DC/ECC возможны только четыре уровня плотности:

| Плотность чистого 17PP | Число байтов |
|---|---:|
| 1/6 = 16,6667% | 28 |
| 1/4 = 25% | 92 |
| 1/3 = 33,3333% | 100 |
| 5/12 = 41,6667% | 36 |

При этом **80 байтов меняют уровень при нечётном битовом смещении**. Вставка DC изменяет фазу разбора двух битов, поэтому ранжировать только по этой таблице голого кодирования нельзя.

| Q | Чистый 17PP | Полный кластер, greedy | Диапазон полного кластера по четырём PSN | Назначение теста |
|---|---:|---:|---:|---|
| `09` | 16,6667% | 19,1997% | 19,1962–19,2080% | самый низкий повторяющийся байт в сканировании |
| `11` | 16,6667% | 19,4820% | 19,4447–19,4820% | чистый код — все 6T, контроль длинных run |
| `22` | 16,6667% | 19,3505% | 19,3242–19,3510% | также устойчивая группа низкой плотности |
| `3D` | 41,6667% | 38,4602% | 38,4428–38,4739% | устойчивый байт высокой плотности |
| `7A` | 41,6667% | 38,5486% | 38,5409–38,5525% | устойчивый байт высокой плотности |
| `9E` | 41,6667% | 38,6143% | 38,6014–38,6260% | самый высокий повторяющийся байт в сканировании |
| `00` | 33,3333% | 32,8615% | 32,8412–32,8668% | контроль обычного ввода |

`55/AA` в полном кластере дают около 32,30% / 32,39% и также не подходят для краёв плотности. Если не компенсировать скремблирование, все измеренные 14 кандидатов из常量 host попадают в диапазон примерно 29,37–29,67%, и исходные различия в основном исчезают.

## Более тонкие достижимые шаблоны

17PP кодирует по правилам переменной длины для 2/4/6/8 входных битов и использует предыдущий modulation bit и специальные правила замены. Байт — это носитель, его нельзя обрабатывать как независимое кодовое слово.

| Исходная периодическая битовая строка | Длина периода | Пример упаковки в байты | Плотность чистого 17PP | Установившийся run |
|---|---:|---|---:|---|
| `0001` | 4 | `11` | 16,6667% | все 6T |
| `00111101` | 8 | `3D` | 41,6667% | 3 × 2T, 2 × 3T |
| `001111` | 6 | `3C F3 CF` | 44,4444% | 3 × 2T, 1 × 3T |
| `0000101101110010` | 16 | `0B 72` | **12,5%** | все 8T |
| `0111011110` | 10 | `77 9D E7 79 DE` | **46,6667%** | 6 × 2T, 1 × 3T |

В обычном сегменте данных 17PP run составляет 2T–8T, и допускается не более шести 2T подряд. Поэтому нижняя граница плотности длинного сегмента данных — `1/8`, верхняя — `7/(6×2+3)=7/15`; указанные 16-битный и 10-битный шаблоны как раз достигают их. Синхронизация содержит 9T, поэтому этот предел нельзя напрямую применять к произвольному короткому окну, включающему синхронизацию.

Два крайних периода при нечётной битовой фазе деградируют до 29,1667% / 33,3333%. 6-битный `001111` при обеих фазах даёт 44,4444%, но коэффициент заполнения голого NRZI равен 4/9 или его дополнению, что требует балансировки DC. В поиске по периодам не длиннее 16 битов это самый устойчивый по чётной и нечётной фазе шаблон высокой плотности.

Пример упаковки лишь показывает, как представить период. **Нельзя напрямую циклически повторять эти host-байты и нельзя просто циклически повторять Q в исходном порядке payload, игнорируя чередование.** Например, при заполнении 6-битного периода Q в порядке payload полный кластер даёт лишь около 33,43–34,39%; при расположении в физическом порядке ECC достигается около 40,64–40,75%.

## Компенсация DC и результаты полного кластера

В каждом кадре 155 ECC bytes, всего 1240 raw bits; сначала идут 25 битов данных, затем после каждых 45 битов данных вставляется один DC bit, всего 28. Пусть `j=8×EccColumn+bitWithinByte`, где bit 0 — MSB:

```text
DCbefore(j) = j < 25 ? 0 : 1 + floor((j - 25) / 45)

Резервирование DC-слота:
index = RecordingFrame × 1268 + j + DCbefore(j)
Qbit = pattern[(index + phase) % period]

Перезапуск по DC-сегменту данных:
index = j < 25 ? j : (j - 25) % 45
Qbit = pattern[(index + phase) % period]
```

После вставки DC начало каждого сегмента оказывается на чётном входном бите, и перезапуск периода сохраняет фазу разбора двух битов. Схема с резервированием слота только резервирует позиции; значения DC-битов по-прежнему выбирает кодировщик/устройство записи. EDC, BIS и parity также нельзя произвольно контролировать — они генерируются нормально.

После построения Q по этим физическим позициям он обратно распределяется по соответствующим payload byte, затем компенсируется скремблирование. Существующий в проекте `Map(luminance, position)` уже предоставляет RecordingFrame/EccColumn; за один вызов можно побитно сгенерировать 8 битов, не ограничивая возвращаемое значение фиксированным байтом.

| Рекомендуемый битовый шаблон | Построение | phase | Полный кластер, greedy | Диапазон по четырём PSN | Диапазон трёх других DC-стратегий |
|---|---|---:|---:|---:|---:|
| 16 бит `0000101101110010` | перезапуск по DC-сегменту | 2 | **15,9500%** | 15,9405–15,9500% | 15,9278–17,0720% |
| 6 бит `001111` | резервирование DC-слота | 3 | **40,8172%** | 40,8158–40,8315% | 41,0010–41,4603% |
| 10 бит `0111011110` | перезапуск по DC-сегменту | 4 | **43,3670%** | 43,3662–43,3713% | 42,1870–43,3904% |

phase начинается с 0 и означает добавление периодического смещения к координате в формуле выше. Каждый кластер снова начинается с начала координат; эти phase относятся только к данному способу построения, а не к произвольному сдвигу всего физического сигнала на одинаковое число битов.

Для 6-битной схемы плотность полного кластера во всех фазах составляет 40,7929–40,8172%, влияние фазы невелико. Крайним 16/10-битным схемам всё ещё нужно сохранять выбранную фазу; при неверной фазе можно вернуться примерно к 30%–32%. Интервал чувствительности к DC — это лишь диапазон нескольких измеренных стратегий, а не гарантированный диапазон для любого устройства записи.

В рекомендуемом низком режиме **52,65% полных inter-transition run составляют 8T**; в рекомендуемом высоком режиме **79,14% составляют 2T**. Это даёт более конкретное сопоставление на реальном диске, чем одно лишь среднее значение плотности. В модели greedy доля уровней NRZI у обоих около 50%, поэтому значения битов 0/1 нельзя напрямую интерпретировать как визуальный чёрный/белый.

## Первые кандидаты для реального диска

Рекомендуется сравнивать следующие чистые цветовые блоки на одинаковом диске, при одинаковой скорости записи и одинаковых условиях наблюдения, повторяя их на внутреннем, среднем и внешнем радиусе:

1. Разреженный край: 16-битный период, перезапуск по DC-сегменту, phase 2.
2. Край высокой плотности: 10-битный период, перезапуск по DC-сегменту, phase 4.
3. Устойчивый контроль высокой плотности: 6-битный период, резервирование DC-слота, phase 3.
4. Базовая линия по байтам: `09`, `11`, `9E`; `00` можно отдельно использовать как контроль обычного ввода.

Сначала на больших блоках сравните фактическую светлоту/темноту и стабильность при изменении угла обзора, затем переходите к смешиванию областей и отображению изображения. Прямое побайтовое чередование двух режимов изменит контекст кодирования, и нельзя предполагать, что его плотность или яркость будет линейным средним двух краёв. Эти крайние по плотности кандидаты ещё не записывались на реальный диск и не использовались для текущего отображения чёрного/белого по умолчанию.

## Проверка и воспроизведение

- Независимая реализация на Python перенесена по стандарту Figure 41; побитно совпадает с C# на 256 четырёхбайтовых векторах и 298 периодических векторах.
- Полный перебор всех 131 068 исходных битовых строк длиной 2–16 с проверкой двух вариантов preceding bit даёт 262 136 точных циклических вычислений; проверены 14 694 класса эквивалентности по двум поворотам. Указанная устойчивая к фазе оптимальность ограничена только этим диапазоном поиска.
- Полная цепочка сканирует все 256 байтов; для синтетических кадров дополнительно проверяются 8 DC mask на каждый байт × 31 позиция синхронизации × 2 варианта termination предыдущего кадра.
- Для тонких шаблонов проверено 176 комбинаций шаблон/компоновка/фаза, дополнительно 120 кластеров повторной проверки адресов. В каждом кластере проверяется, что все 65 536 управляемых Q-байтов находятся в тех же реальных позициях ECC, что и целевые.
- Проверки длины кластера, сохранения числа run и интервалов RLL проходят; быстрое сканирование кластера и полный путь RUB согласуются. В чистых данных нет полных run вне 2T–8T; кластеры с синхронизацией допускают 9T.
