# Формат аудиодорожек CD, порядок байтов и диагностика двоения изображения

## Файлы на диске и диск данных

После выбора папки с файлами на диске на странице дизайна или экспорта проект CD автоматически переключается в режим диска данных ISO9660/Joliet, а суффикс вывода меняется на `.iso`; после очистки пути к папке восстанавливается аудиодорожка WAV. Положение файлов можно выбрать во внутренней или внешней области, по умолчанию — во внутренней; настройка сохраняется вместе с проектом. Метаданные файловой системы по-прежнему находятся в начале диска; режим внешней области размещает содержимое файлов в конце диска, а рисунок сохраняет исходные координаты всего диска и не сжимается в оставшуюся область.

```powershell
DiscImageStudio.exe cd-generate --input picture.png --output cd-image.iso `
  --data-dir "D:\随盘文件" --volume-label CD_IMAGE --file-position outer
```

Длина ISO равна `число секторов × 2048`; запись выполняется как диск данных CD-ROM Mode 1. Мгновенная запись внутри программы использует тот же поток данных ISO; внешнее программное обеспечение для записи должно выбирать функцию записи образа. Переключатель чередования аудио и CUE используются только в режиме аудиодорожки. Область рисунка диска данных отдельно компенсирует скремблирование CD-ROM и отображение позиций; файлы на диске сохраняют исходное содержимое.

Мгновенная запись диска данных CD использует тот же сеанс DAO и ту же проверку границы lead-out, что и аудиодорожка, сохраняя число секторов калибровки ATIP и полную компоновку файлов. Программа кодирует полезную нагрузку ISO в исходные секторы Mode 1 и устанавливает идентификатор дорожки данных; при использовании пресета диска Ritek medical aqua по-прежнему записываются 359 845 секторов данных, а рисунок или файлы не сокращаются под меньшую доступную ёмкость интерфейса TAO. DAO сохраняет ограниченную проверку overburn максимум на 3 сектора, как в режиме аудиодорожки; при превышении выдаётся ошибка до записи.

Дорожка данных использует соглашение IMAPI о little-endian основном канале: на стандартном секторе Mode 1 дополняются EDC, коды коррекции P/Q и выполняется скремблирование, при этом порядок байтов синхросигнала `00 FF…FF 00` сохраняется. Обмен соседних байтов при физическом кодировании CD-ROM и обмен при преобразовании в little-endian взаимно компенсируются; это также согласуется с [RAW-кодированием и преобразованием порядка байтов устройства в cdrdao](https://github.com/cdrdao/cdrdao/blob/master/dao/dao.cc). Компоновка ISO для внутренней и внешней области файлов и отображение физических координат рисунка не меняются от этого соглашения передачи.

Проекция дизайна, уменьшенный предпросмотр тона и чтение готового диска с действительной информацией о компоновке в `.iso.json` выделяют файловую область (включая файловую систему) жёлтым. Одноимённые метаданные записывают геометрию, тон и положение файлов; при перемещении ISO рекомендуется перемещать и их. Предпросмотр показывает отображение полезной нагрузки рисунка; результат на реальном диске по-прежнему требует проверки записью.

## Рекомендуемое использование

Новая задача генерации по умолчанию выводит `cd-track.wav` и одновременно создаёт `cd-track.cue`. WAV — это несжатый PCM: 44,1 kHz, 16 бит, два канала, область данных в little-endian. Поместите эти два файла в один каталог; при перемещении или переименовании также обновляйте имя файла в CUE. CUE необязателен: если на странице экспорта снять флажок «Одновременно экспортировать файл CUE» или передать в командной строке `--cue false`, будет записан только WAV.

| Вход записи | Способ использования |
| --- | --- |
| cdrecord | `cdrecord dev=<устройство> speed=<скорость> -audio "cd-track.wav"`, не добавляйте `-swab` |
| ImgBurn | Откройте `cd-track.cue` в «Write image file to disc» |
| Потоковая запись в программе | Автоматически генерируются те же данные PCM little-endian, без заголовка WAV и без создания полной временной аудиодорожки |
| Старый рабочий процесс RAW | Вывод по-прежнему может быть `.raw`; `cdrecord -audio "cd-track.raw"` без `-swab` |

Суффикс вывода определяет фактический формат; принимаются только `.wav` и `.raw`. Нельзя переименовать старый RAW в WAV; необходимо сгенерировать файл заново. Сопутствующий CUE для WAV использует `FILE "cd-track.wav" WAVE`, а не `BINARY`. Для имён файлов Unicode используется CUE в UTF-8 с BOM, поддерживаются пробелы и китайские символы. Автор ImgBurn проверял поддержку имён Unicode в таком CUE и отмечал, что связанная проблема ранней версии 2.5.0.0 исправлена в 2.5.1.0. [Пояснение автора ImgBurn](https://forum.imgburn.com/topic/13526-unicode-filename-problem-in-cue-file/)

Пример генерации из командной строки (геометрические параметры следует использовать свои измеренные):

```powershell
DiscImageStudio.exe cd-generate --input picture.png --output cd-track.wav --interleave true
```

`--cue` (по умолчанию `true`) управляет тем, записывается ли вместе с WAV одноимённый CUE; для вывода `.raw` CUE всегда не записывается.

Длина файла WAV равна `число секторов × 2352 + 44`; длина аудио, прогресс генерации и ёмкость потоковой записи по-прежнему равны `число секторов × 2352`. Заголовок файла не занимает секторы аудиодорожки диска и не меняет геометрию рисунка.

## Тон (дизеринг, линеаризация sRGB, градации серого и яркость)

Каждый аудиобайт CD соответствует примерно 6,8 µm длины поверхности диска; на нормальном расстоянии просмотра глаз интегрирует сотни и тысячи байтов в один оттенок. Поэтому «каждый байт имеет только два чёрно-белых шаблона» не означает «изображение имеет только два цвета»; промежуточные тона восстанавливаются соотношением чёрных и белых соседних байтов.

| Параметр | Значение |
| --- | --- |
| Интенсивность дизеринга 0–100% | 0% — вывод по жёсткому порогу 128 (старое поведение); 100% — побайтовый выбор между соседними уровнями пропорционально, промежуточный тон формируется пространственным соотношением чёрных и белых байтов |
| Уровни градаций серого (только CD) | 2 уровня используют `0x0D` / `0xAA`; 4 уровня используют `0x0D` / `0x10` / `0x63` / `0xAA` (`0x0D` — чёрный, `0xAA` — белый) |
| Линеаризация sRGB (гамма) | Сначала выполняется декодирование по передаточной функции sRGB, затем дизеринг; изменяется плотность чёрных и белых точек, но не выходные уровни |
| Яркость | Общий сдвиг градаций серого, диапазон −64…+64 (единицы 0..255) |

Параметры командной строки (`cd-generate` и `cd-preview-warp` принимают оба):

```powershell
DiscImageStudio.exe cd-generate --input picture.png --output cd-track.wav `
  --tone-dither 1 --tone-levels 2 --tone-brightness 0 --tone-gamma false
```

Значения по умолчанию: `--tone-dither 0 --tone-levels 2 --tone-brightness 0 --tone-gamma false`, что совпадает со старым побайтовым поведением. Новый проект на странице дизайна в модуле «Тон» по умолчанию использует 75% / 2 уровня; старый проект без раздела `tone` загружается как 0%, а после сохранения записывает раздел `tone`. Страница экспорта сохраняет только параметры вывода и в карточке вывода напоминает, что тон задаётся на странице дизайна.

Фаза дизеринга определяется **индексом логического байта** (`globalByte`), а не экранными координатами. После того как отложенное чередование перемещает байты в файле, предпросмотр при чтении всё равно восстанавливает их по тому же логическому индексу, поэтому генерация, калибровочная проекция и чтение видят один и тот же набор шаблонов. Калибровочный шаблон (`GeneratePattern`) всегда использует жёсткий порог и не участвует в дизеринге.

Одноимённый `.json` рядом с аудиодорожкой записывает `toneDitherStrength`, `toneLevels`, `toneBrightness`, `toneSrgbLinearization`; страница предпросмотра при загрузке внешней аудиодорожки синхронизирует эти значения вместе с геометрией и чередованием.

Чтение для предпросмотра по умолчанию использует 1600 px и 16 выборок на сектор, а выборки, попадающие в один пиксель, **суммируются и усредняются**. Старая версия фиксированно использовала 900 px и 2 выборки на сектор с перезаписью более поздними значениями; разреженная выборка оставляла белые точки в промежуточных тонах, похожие на газетный растр; после повышения плотности выборки одна и та же поверхность диска выглядит как непрерывный тон. «Проекция дизайна» на странице предпросмотра по умолчанию задаёт измеренную геометрию равной геометрии проекта, поэтому при открытии проекта получается нейтральная проекция; отклонение двух наборов геометрии отображается только после ввода измеренных радиусов.

## Подтверждённые проблемы

Пользовательское сравнение на реальном диске 2026-09-12: один и тот же существующий RAW нормально работал с `-audio` и `speed` в cdrecord; при добавлении `-swab` воспроизводилось двоение. Это подтвердило, что существующий RAW следует интерпретировать как big-endian аудиовход по умолчанию cdrecord.

Ранее экспорт файла и потоковая запись использовали совершенно одинаковый вывод `GenerateToStream`, и потоковый путь не выполнял преобразование порядка байтов. Но соглашения разных входов различаются:

| Вход | Требование к аудиоданным |
| --- | --- |
| cdrecord без заголовка `-audio` | по умолчанию big-endian |
| cdrecord без заголовка `-audio -swab` | little-endian; этот параметр объявляет необходимость обмена порядка входных данных |
| cdrecord WAV | анализирует заголовок файла и автоматически определяет порядок байтов аудио |
| CUE `FILE ... BINARY` | little-endian; нельзя напрямую подставлять существующий big-endian RAW в BINARY CUE |
| IMAPI `AddTrack(IMAPI_CD_SECTOR_AUDIO, stream)` | та же компоновка сэмплов, что и область данных WAV 16 бит, два канала, 44,1 kHz, то есть PCM little-endian без заголовка |

Указанное поведение cdrecord и определение BINARY взяты из [официального руководства cdrecord](https://cdrtools.sourceforge.net/private/man/cdrecord/cdrecord.1.html); компоновка аудиосэмплов IMAPI — из [определения AUDIO-сектора Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/ne-imapi2-imapi_cd_sector_type). Автор ImgBurn также приводил пример успешной записи CUE `FILE ... WAVE`. [Пример WAVE CUE для ImgBurn](https://forum.imgburn.com/topic/25173-extract-only-session-two-from-audio-cd/page/2/)

Здесь `AudioSectorType = 0` — это значение AUDIO из перечисления IMAPI, а не запись аудиодорожки как физического Mode 0. `IRawCDImageCreator::AddTrack` сейчас поддерживает только тип AUDIO. [Документация Microsoft AddTrack](https://learn.microsoft.com/en-us/windows/win32/api/imapi2/nf-imapi2-irawcdimagecreator-addtrack)

## Почему образуются два контура

Существующий `CddaInterleaver` выполняет задержочную компенсацию для целевых байтов. Обмен двух байтов каждого 16-битного сэмпла в конечном выводе交叉но подаёт в цепочку кодирования байты, изначально принадлежавшие разным позициям задержки. Поэтому изменение нельзя понимать как обычное изменение аудиозначений и нельзя один раз поменять байты до выборки изображения, чтобы это компенсировать.

Эксперимент с перестановкой целочисленных меток для существующей таблицы задержек, после исключения заполнения в начале и конце, показывает, что дополнительный обмен байтами сэмплов сдвигает чётные позиции после обратного отображения на `+73` целевых байта, а нечётные — на `-73` целевых байта. Это объясняет механизм двух контуров; это вывод из модели задержочной перестановки программы, а не полная модель CIRC оптического привода и не измерение на физическом диске.

Исправление сохраняет выборку и таблицу задержек и выбирает порядок байтов на границе вывода сектора 2352 байта после завершения компенсации: старый RAW — big-endian; WAV и IMAPI — little-endian. Заголовок файла WAV решает задачу распознавания формата и порядка байтов внешними инструментами; потоковый интерфейс по-прежнему принимает только область данных согласно своему соглашению.

## Чтение должно компенсировать отложенное чередование

Задержочная компенсация сдвигает логический байт i в индекс файла `i + offset(i % 24)`: таблица чередования хранится в линии задержки 28×D (D=4) кадров, по 24 байта в кадре, поэтому смещение находится между 72 и 2592 (сумма задержки кадра и поворота столбца внутри кадра). Если просто раскладывать байты в порядке файла по спирали, рисунок целиком повернётся и сдвинется — при сравнении одного и того же изображения на 60 000 секторах и 900 px около 17,5% отрисованных пикселей не совпадут с исходным изображением, что выглядит как «лёгкое искажение».

Поэтому `cd-preview-track` по умолчанию выполняет обратное отображение (`--deinterleave`, по умолчанию `true`): логический байт i берёт индекс файла `i + CddaInterleaveTable.FileOffsetFor(i % 24)`, требуется окно предпросмотра на 2592 байта. Прямая задержка этой таблицы использует общий `CddaInterleaveTable` с `CddaInterleaver`, поэтому стороны не могут разойтись независимо.

Цена в хвосте: линия задержки в конце файла всё ещё содержит последние несколько кадров, эти логические байты не были записаны (1318–1332 байта, меньше одного сектора), и при чтении их можно только оставить пустыми. Они находятся на самом внешнем кольце аудиодорожки, и их доля во всей дорожке падает с ростом числа секторов.

`cd-generate` теперь записывает рядом с аудиодорожкой `<track>.json` (`format: cd-da-track-v1`, содержит r0/r1/число секторов/линейную скорость/начальный угол/внешний радиус изображения/признак чередования). Рабочая область предпросмотра при переключении аудиодорожки читает его и загружает калибровочную геометрию и переключатель чередования, поэтому аудиодорожка, созданная на другой машине, также читается по правильной модели.

## Калибровочная проекция: исходное изображение и два набора геометрии

`cd-preview-warp` — быстрый контроль пути чтения, а также команда, вызываемая режимом «Калибровочный предпросмотр» рабочей области предпросмотра: на вход подаётся исходное изображение, а не аудиодорожка; параметрами являются два набора геометрии — генерирующая геометрия определяет, из какого места изображения берётся i-й байт, а измеренная геометрия определяет, в каком месте поверхности диска этот байт рисуется (`--actual-r0`, `--actual-r1`, по умолчанию 24,3 / 56,6 мм). При совпадении обоих наборов геометрии проекция равна исходному изображению; при различии рисунок смещается по измеренной поверхности диска — именно это явление и нужно наблюдать при калибровке радиусов. Число секторов, линейная скорость, начальный угол и внешний радиус изображения общие для обоих наборов геометрии; последние три фиксированы как 1200 mm/s, 0°, 57,5 мм.

Поскольку команда читает только исходное изображение и не сканирует всю аудиодорожку, стоимость обновления после изменения радиусов или геометрии определяется размером изображения, а не размером аудиодорожки (для 80-минутного диска около 845 MB), что удобно для подбора параметров в калибровочном предпросмотре и последующего подтверждения итоговой поверхности диска моделированием чтения.

## Проверка и границы

- RAW и WAV: для несимметричного рисунка как при включённом, так и при выключенном чередовании область data WAV строго равна последовательности байтов старого RAW после попарного обмена каждого 16-битного значения; длина сохраняется.
- Потоковый вывод: в прямом потоке с запретом Seek/Position генерируется little-endian аудио, результат побайтно равен области data WAV и не содержит заголовка файла.
- Предпросмотр WAV: анализируются `fmt ` / `data` RIFF, пропускаются неизвестные блоки и заполнение нечётной длины, ограничивается диапазон чтения, нормализуется порядок байтов; отклоняются данные не PCM, не 44,1 kHz, не 16-битные или не двухканальные. При разных шагах выборки результат совпадает с соответствующим предпросмотром RAW. Предпросмотр по-прежнему является отображением байтов файла, не моделирует полный физический CIRC/EFM и не может заменить проверку на реальном диске.
- Согласованность чтения: из одного исходного изображения отдельно генерируются аудиодорожки с чередованием и без него; чтение с `--deinterleave true` чередованной дорожки и чтение в порядке файла нечередованной дорожки дают попиксельно одинаковый результат, кроме пикселей в пределах одного сектора в хвосте линии задержки (при 900 px и несимметричном тестовом изображении различия попадают только в хвостовую проекцию; мутационный тест при изменении задержки кадра на 24 байта сообщает о 245 несовпадениях).
- Согласованность калибровочной проекции: из одного исходного изображения сначала генерируется аудиодорожка по генерирующей геометрии `(24,5, 56,8)`, затем проекция `cd-preview-warp` (измеренная = генерирующей, измеренная = `24,3/56,6`) попиксельно сравнивается с результатом чтения `cd-preview-track` с соответствующей геометрией; после пороговой обработки результаты полностью совпадают (900 px); при уменьшении измеренного радиуса радиус центра тяжести проекции уменьшается, поэтому два набора геометрии не смешиваются.
- Эксперимент с памятью Windows: в существующий `MsftRawCDImageCreator` подаются 300 несимметричных аудиосекторов, сканируется полный сектор RAW размером 2448 байт, все аудиобайты сохраняются как есть. Генератор не обменивает байты за вызывающий код. Тест не создаёт устройство записи и не пишет на диск.
